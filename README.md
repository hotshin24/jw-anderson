# JW Anderson — E-Commerce Redesign

럭셔리 패션 브랜드 JW Anderson의 이커머스 사이트를 **에디토리얼 감성으로 재해석한 리디자인 프로젝트**입니다.
기존 사이트가 브랜드의 가격대에 비해 시각적으로 저평가되어 보인다는 문제의식에서 출발해, 웜 뉴트럴 팔레트와 세리프·산세리프 이중 타이포그래피 체계를 도입하고 상품 그리드 사이에 에디토리얼 섹션을 배치했습니다.

## 1. 이 프로젝트에서 가장 공들인 것 — CSS 아키텍처 리팩터링

393페이지 규모를 구현한 뒤, **동작하는 코드를 유지보수 가능한 코드로 다시 만드는 작업**에 전체 일정의 상당 부분을 투입했습니다. 이 과정을 34개의 구획 단위 커밋으로 기록했으며, 커밋 로그만으로 작업 순서와 근거를 추적할 수 있습니다.

### 문제 인식

초기 구조는 데스크탑·태블릿·모바일 세 계층이 각각 완결된 레이아웃을 갖는 **완전 병렬 구조**였습니다. 동작에는 문제가 없었지만, 측정해보니 계층 간 선택자 중복률이 **92~97%**였습니다. 버튼 하나를 수정하려면 세 곳을 고쳐야 하는 상태였고, 이는 규모가 커질수록 유지보수 비용이 선형으로 증가하는 구조입니다.

이 중복은 사고가 아니라 **인지된 트레이드오프**였습니다. 모바일 구현 시점에는 "커버리지를 먼저 닫는다"는 판단으로 계층 완전 기술 방식을 택했고, 중복 제거는 동작이 완결된 뒤 상환하기로 미뤄둔 부채였습니다. 커버리지와 중복 제거를 동시에 풀려다 둘 다 늦어지는 것을 피한 순서 판단입니다.

### 해결 — 공통 승격 + 차이분 오버라이드

계층별로 값이 동일한 규칙을 미디어쿼리 밖 **base 층으로 승격**하고, 각 계층에는 실제로 달라지는 선언만 남겼습니다.

```
[Before]  모바일 전체 레이아웃 | 태블릿 전체 레이아웃 | 데스크탑 전체 레이아웃
[After]   base 공통 규칙 + 계층별 차이분만
```

| 파일 | Before | After | 감축 |
|---|---|---|---|
| global.css | 5,312줄 | 2,780줄 | **-47.7%** |
| page.css | 9,732줄 | 5,868줄 | **-39.7%** |

최종 구조에서 base 층이 전체의 **41.6%**(global 1,597줄 / page 2,069줄)를 차지하고, 각 계층 블록에는 그 뷰포트에서 실제로 달라지는 선언만 남습니다. **"이 규칙이 왜 여기 있는가"의 답이 블록 위치 자체가 되는 것**이 이 구조의 목적입니다.

### 검증 — 유실 사고와 그 이후

컴포넌트·컨테이너 단위로 구획을 나눠 순차 진행했고(`selectComponent`, `bx-slider`, `aside` 계열, `accountContainer`, `checkoutContainer` 등), 각 구획마다 **이동 전후의 유효 스타일을 전수 대조**했습니다. 이동·병합 자체는 전량 수작업으로 진행하되 검증에는 자동 대조를 병행했으며, **검증 도구의 산출물 역시 검수 대상**으로 삼아 분류 누락·오진 등 도구 측 오류 4건을 사람 검토로 걸러냈습니다.

global.css에서 먼저 파이프라인(구획 분석 → 이동 → 누락 검증 → 병합 → 토큰 치환 → `:is()` 압축)을 확립·검증한 뒤 page.css에 재적용했고, 이때 컨테이너 간 **공유 구조를 먼저 추출하는 방식으로 전략을 발전**시켰습니다.

작업 전 과정에서 유실은 총 3차례 발생했습니다 — 단일 선택자 유실 2건과, 컨테이너 병합 지도의 생략 결함으로 인한 **선택자 40개 유실 1건**. 세 건 모두 전수 대조 검증에서 검출되어 즉시 복구했고, 40개 유실 건을 계기로 **선택자 수 검산을 구획 완료 조건에 추가**했습니다. 최종 회귀 검증은 모바일·태블릿·데스크탑에 더해 1280~1890px 세부 블록까지 범위를 넓혀 **회귀 0건**으로 마감했습니다.

### 선택자 압축

동일 본문을 공유하며 병렬 나열되던 선택자 그룹은 `:is()`로 병합했습니다(74그룹).

```css
/* Before */
#popupSignIn.active,
#popupForgottenPassword.active,
#popupCreateAccount.active,
... (11개 나열)

/* After */
:is(#popupSignIn, #popupForgottenPassword, #popupCreateAccount, ...).active
```

적용은 특정도(specificity) 검토를 전제로 했습니다. `:is()`는 인자 중 가장 높은 특정도를 따르므로 병합 시 오버라이드 관계가 바뀔 수 있는데, 이에 해당하는 **29개 그룹은 근거를 기록하고 보류**했습니다. 압축률보다 캐스케이드의 예측 가능성을 우선한 판단입니다.

## 2. 디자인 토큰 체계

색상과 간격 전량을 `module.css`의 커스텀 프로퍼티로 관리합니다. **하드코딩된 색상값은 global.css·page.css 전수 검증 기준 0건**입니다(reset.css의 브라우저 기본값 보정 5건은 보일러플레이트로 제외).

```css
:root {
  /* 색상 — 계열 + 명도 순번 */
  --gs00 ~ --gs07   /* grayscale 8단 */
  --be01, --be02    /* beige — 시그니처 웜 뉴트럴 */
  --ac01, --ac02    /* accent */
  --rd01            /* red — 기능·상태 */
  --ov10, --ov40    /* overlay (알파) */

  /* 간격 — 5px 스케일 */
  --sp05 ~ --sp150  /* 18단 (323곳 적용) */

  /* 간격 — 역할 기반 */
  --gutter, --gutter-header, --section-y
}
```

색상 계열을 명도 순번으로 정렬한 덕분에, 개발 중반 배경 팔레트를 전면 교체했을 때 UI 39곳을 개별 수정하지 않고 **토큰 정의부만 변경해 전체에 반영**했습니다.

토큰 운용에는 "죽은 토큰을 남기지 않는다"는 원칙을 적용했습니다. 정의만 해두고 사용처가 없던 `--block-gap`은 적용 계획을 재검토한 뒤 **폐기**했습니다.

### 간격 토큰 — 브레이크포인트 재정의 방식

역할 기반 토큰은 **값을 브레이크포인트마다 갈아끼우는** 방식으로 운용하며, 현재 헤더·푸터·팝업 등 **공통 컴포넌트 층(global.css)에 적용**되어 있습니다.

```css
/* 기본값 = 모바일 (모바일 퍼스트) */
:root { --gutter: 10px; }

/* 태블릿·데스크탑에서 토큰 값만 재정의 */
@media (min-width: 768px) and (max-width: 1279px) { :root { --gutter: 70px; } }
@media (min-width: 1280px)                        { :root { --gutter: 70px; --gutter-header: 3.9%; } }

/* 규칙은 계층별로 반복하지 않고 한 번만 선언 */
#popupEmailSignUp { padding: var(--section-y) var(--gutter); }
```

기존에는 팝업 하나의 좌우 여백을 위해 세 계층에 규칙을 세 번 썼습니다. 토큰 재정의 방식으로 바꾸면서 규칙은 한 번만 남고, 여백 정책 변경 시 **재정의 한 줄만 수정**하면 전체에 반영됩니다.

기본값을 모바일 값으로 둔 것은 의도적입니다. 미디어쿼리 구간에 틈이 생기더라도 좁은 여백으로 폴백되어 콘텐츠가 깨지지 않기 때문입니다.

## 3. 반응형 전략

```
≤767px          모바일 — 1열, 아코디언 내비게이션
768px–1279px    태블릿 — 2열 그리드, 인라인 아코디언 내비게이션
≥1280px         데스크탑 — 메가메뉴, 4열 그리드
  ├ 1280–1500px   PLP 2열
  ├ 1501–1890px   PLP 3열
  └ ≥1891px       PLP 4열
```

**1280px을 데스크탑 기준으로** 잡은 것은 메가메뉴(5개 카테고리 + 서브메뉴 + 프로모션 타일)가 겹침 없이 배치되는 최소 폭이기 때문입니다. 임의의 관례값이 아니라 콘텐츠가 요구하는 폭에서 역산했습니다.

데스크탑 내부에서도 PLP 카드가 늘어지지 않도록 열 수를 단계적으로 조정했습니다. "데스크탑 = 고정 레이아웃"이 아니라 콘텐츠가 버티는 한계 폭을 기준으로 구간을 나눴습니다.

### 내비게이션 패턴 전환

| 데스크탑 | 태블릿 / 모바일 |
|---|---|
| 호버 메가메뉴 | 탭 기반 인라인 아코디언 |
| 프로모션 이미지 타일 노출 | 타일 숨김 (리스트 간결화) |
| 유틸리티 메뉴 전체 노출 | 핵심(메뉴·로고·카트)만 유지 |

터치 환경에는 호버가 없으므로 메가메뉴를 축소하지 않고 **패턴 자체를 교체**했습니다. 풀스크린 오버레이 대신 인라인 아코디언을 택한 이유는, 카테고리 5개 × 서브 4~11개 구조에서 풀스크린 메뉴는 뎁스 이동 시 현재 위치 감각을 잃기 때문입니다. 아코디언은 상위 목록을 계속 노출합니다.

모바일 내비게이션은 `<input type="checkbox">` + `<label>` 구조로 구현해 **JavaScript 없이도 동작**하도록 했습니다.

## 4. 문제 해결 기록

### 실제 커머스를 재현한 대가 — Google Safe Browsing 경고 대응

배포 후, 사이트가 **Google Safe Browsing에 기만적 사이트(deceptive site)로 등재**되어 브라우저 경고가 노출되는 문제가 발생했습니다. 로그인·결제·주소 입력 폼을 실제 커머스 수준으로 재현한 것이 자동 탐지 기준에 걸린 것입니다. 링크를 여는 사람이 경고 화면부터 보게 되는, 포트폴리오로서 치명적인 상황이었습니다.

**대응** — "이 사이트가 실제 거래를 하지 않는다"는 사실을 사람과 기계 양쪽이 읽을 수 있게 세 계층으로 명시했습니다.

| 조치 | 범위 |
|---|---|
| 전 입력 요소 `autocomplete="off"` — 브라우저 자동완성·자격증명 저장 차단 | 5,159개 |
| 페이지 타이틀에 `(Portfolio)` 표기 | 전 페이지 |
| 푸터 고지 — 비상업 학습 목적, 브랜드 비제휴, 실제 결제·개인정보 미수집 | 전 페이지 |

이후 재심사를 신청해 해결했습니다. 배포된 사이트는 **탐지 시스템의 판단 대상**이 되며, 재현도가 높을수록 오탐 가능성도 함께 올라간다는 것을 실제 사례로 확인한 작업이었습니다.

### 팝업 기본 숨김이 데스크탑에만 적용되던 구조적 버그

반응형 작업 중, 태블릿 폭에서 로그인·장바구니·검색 패널이 **페이지 본문 사이에 전부 펼쳐진 채 렌더링**되는 문제를 발견했습니다.

원인은 팝업·패널의 `display: none` 기본값이 `@media (min-width: 1280px)` 블록 안에 갇혀 있던 것이었습니다. 데스크탑에서는 정상이지만 그 외 폭에서는 "숨김" 자체가 적용되지 않았습니다.

**해결** — "기본 상태는 화면 크기와 무관하다"는 원칙으로 숨김 규칙을 미디어쿼리 밖 전역 스코프로 분리하고, `.active` 토글만 상태 규칙으로 남겼습니다. 이후 브레이크포인트를 추가해도 팝업 시스템을 다시 손댈 필요가 없어졌습니다.

### 반응형 이미지 오버플로우

배너·컬렉션 이미지가 고정 폭으로 지정되어 좁은 화면에서 가로 스크롤을 유발했습니다. 개별 이미지를 수정하는 대신 전역 안전장치를 두고, 예외가 필요한 곳만 개별 재정의하는 방식을 택했습니다.

```css
img { max-width: 100%; height: auto; }
```

## 5. 접근성

- **시맨틱 마크업** — `header / nav / main / section / figure / footer` 랜드마크 구조, 페이지당 단일 `h1`, 브레드크럼 `nav > ol`
- **대체 텍스트** — 이미지 13,502개 전량에 콘텐츠 기반 `alt` 작성. 빈 `alt` 0건이며, 상품 이미지는 색상·소재 등 식별 정보를 포함합니다 (예: `alt="Loafer bag in pine green alligator leather"`)
- **명도 대비** — 본문 `--gs05`(#333) / 배경 `--be01`(#f3ede3) 대비율 **10.84 : 1** — WCAG AA 기준(4.5:1)을 크게 상회
- **폼 라벨** — 입력 요소에 `label[for]` 연결, 플레이스홀더로 라벨을 대체하지 않음
- **커스텀 컨트롤** — 체크박스 커스터마이징 시 `display: none` 대신 시각적 숨김 처리로 키보드 포커스 유지
- **터치 타겟** — 모바일·태블릿 내비게이션 항목 높이 44px 이상
- **확대 대응** — 폰트 크기의 순수 `vw` 단위 사용을 배제하는 원칙 적용 (사용자 확대 무력화 방지, WCAG 1.4.4). 잔여 8건은 `clamp()` 전환 예정

## 6. 한계와 다음 단계

현재 구조에서 스스로 인지하고 있는 한계입니다.

1. **토큰 체계 이행 잔여** — 두 가지가 남아 있습니다. ⓐ `--c-text`, `--c-bg` 등 용도 기반 별칭 계층을 정의했으나 컴포넌트 CSS는 아직 원시 토큰(`var(--gs05)`)을 직접 참조합니다. 별칭 마이그레이션이 완료되면 "브랜드 색 교체"와 "용도 변경"을 분리해 다룰 수 있게 됩니다. ⓑ 역할 간격 토큰(`--gutter`, `--section-y`)은 공통 컴포넌트 층까지 적용된 상태로, 페이지 레이아웃 층(page.css)으로의 확장이 다음 단계입니다.
2. **위치 기반 셀렉터 의존** — `header>div div:nth-of-type(2)` 형태의 구조 종속적 셀렉터가 다수 존재합니다. 마크업 순서가 바뀌면 스타일이 깨지는 취약성이 있어, 차기 프로젝트에서는 SCSS + BEM 기반 클래스 설계로 전환합니다.
3. **키보드 포커스 스타일** — `:focus-visible` 스타일이 아직 정의되지 않았습니다. 접근성 항목 중 우선 보완 대상입니다.
4. **이미지 최적화** — PNG 원본 기준이라 용량이 큽니다. `loading="lazy"`, `width/height` 명시(CLS 방지), WebP 변환, `srcset` 해상도 분기가 다음 개선 항목입니다.
5. **CSS 로드 방식** — 현재 `@import` 체인은 직렬 로딩됩니다. `<link>` 병렬 로드와 폰트 `preconnect`로 전환 예정입니다.
6. **상태 관리 부재** — 장바구니·위시리스트가 화면 표현에 머물러 새로고침 시 초기화됩니다. `localStorage` 기반 지속성 부여가 다음 기능 과제입니다.
7. **jQuery 의존** — 학습 곡선상의 선택이었으며, 인터랙션 로직의 Vanilla JS 전환을 검토 중입니다.

## 프로젝트 구조

```
├── index.html ~ 392 pages
├── css/
│   ├── import.css      # 로드 순서 관리 (reset → module → global → page)
│   ├── reset.css       # L0 초기화
│   ├── module.css      # L1 디자인 토큰 (색상·간격)
│   ├── global.css      # L3 전역 공통 (헤더, 푸터, 팝업, 버튼)
│   └── page.css        # L4 페이지별 레이아웃
├── js/
│   ├── jwanderson.js   # 인터랙션 108개 함수 (패널, 아코디언, 폼, 슬라이더 초기화)
│   ├── jquery.bxslider.js
│   └── jquery.fitvids.js
├── images/
└── video/
```

`global.css`와 `page.css`는 각각 내부적으로 `base 공통 → 모바일(≤767) → 태블릿(768–1279) → 데스크탑(≥1280)` 순으로 구성되어 있습니다.
