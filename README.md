럭셔리 패션 브랜드 JW Anderson의 이커머스 사이트를 **에디토리얼 감성으로 재해석한 리디자인 프로젝트**입니다.

## 1. 이 프로젝트에서 가장 공들인 것 — CSS 아키텍처 리팩터링

392페이지 규모를 구현한 뒤, **동작하는 코드를 유지보수 가능한 코드로 다시 만드는 작업**에 전체 일정의 상당 부분을 투입했습니다. 이 과정을 34개의 구획 단위 커밋으로 기록했으며, 커밋 로그만으로 작업 순서와 근거를 추적할 수 있습니다.

### 문제 인식

초기 구조는 데스크탑·태블릿·모바일 세 계층이 각각 완결된 레이아웃을 갖는 **완전 병렬 구조**였습니다. 동작에는 문제가 없었지만, 측정해보니 계층 간 선택자 중복률이 **92~97%**였습니다. 버튼 하나를 수정하려면 세 곳을 고쳐야 하는 상태였고, 이는 규모가 커질수록 유지보수 비용이 선형으로 증가하는 구조입니다.

이 중복은 사고가 아니라 **인지된 트레이드오프**였습니다. 모바일 구현 시점에는 "커버리지를 먼저 닫는다"는 판단으로 계층 완전 기술 방식을 택했고, 중복 제거는 동작이 완결된 뒤 상환하기로 미뤄둔 부채였습니다. 커버리지와 중복 제거를 동시에 풀려다 둘 다 늦어지는 것을 피한 순서 판단입니다.

### 해결 — 공통 승격 + 차이분 오버라이드

계층별로 값이 동일한 규칙을 미디어쿼리 밖 **base 층으로 승격**하고, 각 계층에는 실제로 달라지는 선언만 남겼습니다.

```
[Before]  모바일 전체 레이아웃 | 태블릿 전체 레이아웃 | 데스크탑 전체 레이아웃
[After]   base 공통 규칙 + 계층별 차이분만
```

| 파일 | Before | After | 감축 |
|---|---|---|---|
| global.css | 5,312줄 | 2,780줄 | **-47.7%** |
| page.css | 9,732줄 | 5,852줄 | **-39.9%** |

최종 구조에서 base 층이 전체의 **41.6%**(global 1,597줄 / page 2,067줄)를 차지하고, 각 계층 블록에는 그 뷰포트에서 실제로 달라지는 선언만 남습니다. **"이 규칙이 왜 여기 있는가"의 답이 블록 위치 자체가 되는 것**이 이 구조의 목적입니다.

### 검증 — 유실 사고와 그 이후

컴포넌트·컨테이너 단위로 구획을 나눠 순차 진행했고(`selectComponent`, `bx-slider`, `aside` 계열, `accountContainer`, `checkoutContainer` 등), 각 구획마다 **이동 전후의 유효 스타일을 전수 대조**했습니다. 이동·병합 자체는 전량 수작업으로 진행하되 검증에는 자동 대조를 병행했으며, **검증 도구의 산출물 역시 검수 대상**으로 삼아 분류 누락·오진 등 도구 측 오류 4건을 사람 검토로 걸러냈습니다.

global.css에서 먼저 파이프라인(구획 분석 → 이동 → 누락 검증 → 병합 → 토큰 치환 → `:is()` 압축)을 확립·검증한 뒤 page.css에 재적용했고, 이때 컨테이너 간 **공유 구조를 먼저 추출하는 방식으로 전략을 발전**시켰습니다.

작업 전 과정에서 유실은 총 3차례 발생했습니다 — 단일 선택자 유실 2건과, 컨테이너 병합 지도의 생략 결함으로 인한 **선택자 40개 유실 1건**. 세 건 모두 전수 대조 검증에서 검출되어 즉시 복구했고, 40개 유실 건을 계기로 **선택자 수 검산을 구획 완료 조건에 추가**했습니다. 최종 회귀 검증은 모바일·태블릿·데스크탑에 더해 1280~1918px 세부 블록까지 범위를 넓혀 **회귀 0건**으로 마감했습니다.

### 선택자 압축

동일 본문을 공유하며 병렬 나열되던 선택자 그룹은 `:is()`로 병합했습니다(74그룹).

```css
/* Before */
#popupSignIn.active,
#popupForgottenPassword.active,
#popupCreateAccount.active,
... (11개 나열)

/* After */
:is(#popupSignIn, #popupForgottenPassword, #popupCreateAccount, ...).active
```

적용은 특정도(specificity) 검토를 전제로 했습니다. `:is()`는 인자 중 가장 높은 특정도를 따르므로 병합 시 오버라이드 관계가 바뀔 수 있는데, 이에 해당하는 **29개 그룹은 근거를 기록하고 보류**했습니다. 압축률보다 캐스케이드의 예측 가능성을 우선한 판단입니다.

## 2. 디자인 토큰 체계

색상과 간격 전량을 `module.css`의 커스텀 프로퍼티로 관리합니다. **하드코딩된 색상값은 CSS 8,806줄 전수 검증 기준 0건**입니다 — hex·rgb뿐 아니라 `white` 같은 색상 키워드까지 포함하며, 보일러플레이트인 `reset.css`도 예외로 두지 않았습니다.

```css
:root {
  /* 색상 — 계열 + 명도 순번 */
  --gs00 ~ --gs07   /* grayscale 8단 */
  --be01, --be02    /* beige — 시그니처 웜 뉴트럴 */
  --ac01, --ac02    /* accent */
  --rd01            /* red — 기능·상태 */
  --ov10, --ov40    /* overlay (알파) */

  /* 간격 — 5px 스케일 */
  --sp05 ~ --sp150  /* 18단 (323곳 적용) */

  /* 간격 — 역할 기반 */
  --gutter, --gutter-header, --section-y
}
```

색상 계열을 명도 순번으로 정렬한 덕분에, 개발 중반 배경 팔레트를 전면 교체했을 때 UI 39곳을 개별 수정하지 않고 **토큰 정의부만 변경해 전체에 반영**했습니다.

토큰 운용에는 "죽은 토큰을 남기지 않는다"는 원칙을 적용했습니다. 정의만 해두고 사용처가 없던 `--block-gap`은 적용 계획을 재검토한 뒤 **폐기**했습니다.

### 간격 토큰 — 브레이크포인트 재정의 방식

역할 기반 토큰은 **값을 브레이크포인트마다 갈아끼우는** 방식으로 운용하며, 현재 헤더·푸터·팝업 등 **공통 컴포넌트 층(global.css)에 적용**되어 있습니다.

```css
/* 기본값 = 모바일 값 */
:root { --gutter: 10px; }

/* 태블릿·데스크탑에서 토큰 값만 재정의 */
@media (min-width: 768px) and (max-width: 1279px) { :root { --gutter: 70px; } }
@media (min-width: 1280px)                        { :root { --gutter: 70px; --gutter-header: 3.9%; } }

/* 규칙은 계층별로 반복하지 않고 한 번만 선언 */
#popupEmailSignUp { padding: var(--section-y) var(--gutter); }
```

기존에는 팝업 하나의 좌우 여백을 위해 세 계층에 규칙을 세 번 썼습니다. 토큰 재정의 방식으로 바꾸면서 규칙은 한 번만 남고, 여백 정책 변경 시 **재정의 한 줄만 수정**하면 전체에 반영됩니다.

토큰 기본값을 모바일 값으로 둔 것은 의도적입니다. 미디어쿼리 구간에 틈이 생기더라도 좁은 여백으로 폴백되어 콘텐츠가 깨지지 않기 때문입니다. 반면 **레이아웃 자체는 데스크탑을 기준선으로 두고 좁은 폭을 예외 처리**합니다(§3). 토큰 층과 레이아웃 층의 기준이 서로 다른데, 각각 오버라이드 총량이 최소가 되는 방향으로 정한 결과입니다.

## 3. 반응형 전략

```
≤767px          모바일 — 1열, 아코디언 내비게이션
768px–1279px    태블릿 — 2열 그리드, 인라인 아코디언 내비게이션
≥1280px         데스크탑 — 메가메뉴
  ├ 1280–1500px   PLP 2열
  ├ 1501–1918px   PLP 3열
  └ ≥1919px       PLP 4열
```

**1280px을 데스크탑 기준으로** 잡은 것은 메가메뉴(5개 카테고리 + 서브메뉴 + 프로모션 타일)가 겹침 없이 배치되는 최소 폭이기 때문입니다. 임의의 관례값이 아니라 콘텐츠가 요구하는 폭에서 역산했습니다.

데스크탑 내부에서도 PLP 카드가 늘어지지 않도록 열 수를 단계적으로 조정했습니다. 미디어쿼리는 `min-width: 1280px`을 데스크탑 계층의 기본값으로 두고, 그 안에서 1280–1500 · 1501–1918 두 구간이 **열 수만 차분 오버라이드**합니다. 4열이 실제로 적용되는 폭이 1919px 이상인 것은 이 캐스케이드의 결과입니다. §1의 "공통 승격 + 차분 오버라이드" 전략을 데스크탑 내부에도 동일하게 적용했습니다.

PLP 좌우에 고정 배치된 장식 영상과 4열 그리드가 1918px 이하에서 겹치기 때문에, 겹침이 시작되는 폭을 실측해 경계값을 정했습니다.

### 내비게이션 패턴 전환

| 데스크탑 | 태블릿 / 모바일 |
|---|---|
| 호버 메가메뉴 | 탭 기반 인라인 아코디언 |
| 프로모션 이미지 타일 노출 | 타일 숨김 (리스트 간결화) |
| 유틸리티 메뉴 전체 노출 | 핵심(메뉴·로고·카트)만 유지 |

터치 환경에는 호버가 없으므로 메가메뉴를 축소하지 않고 **패턴 자체를 교체**했습니다. 풀스크린 오버레이 대신 인라인 아코디언을 택한 이유는, 카테고리 5개 × 서브 4~11개 구조에서 풀스크린 메뉴는 뎁스 이동 시 현재 위치 감각을 잃기 때문입니다. 아코디언은 고정 헤더(62px) 바로 아래에 전체 폭으로 펼쳐지며 상위 목록을 계속 노출합니다.

모바일 내비게이션은 `<input type="checkbox">` + `<label>` 구조로 구현해 **JavaScript 없이도 동작**하도록 했습니다(다만 §6-3의 한계가 있습니다).

## 4. 문제 해결 기록

### 실제 커머스를 재현한 대가 — Google Safe Browsing 경고 대응

배포 후, 사이트가 **Google Safe Browsing에 기만적 사이트(deceptive site)로 등재**되어 브라우저 경고가 노출되는 문제가 발생했습니다. 로그인·결제·주소 입력 폼을 실제 커머스 수준으로 재현한 것이 자동 탐지 기준에 걸린 것입니다. 링크를 여는 사람이 경고 화면부터 보게 되는, 포트폴리오로서 치명적인 상황이었습니다.

**대응** — "이 사이트가 실제 거래를 하지 않는다"는 사실을 사람과 기계 양쪽이 읽을 수 있게 세 계층으로 명시했습니다.

| 조치 | 범위 |
|---|---|
| 자격증명·개인정보 입력 요소 `autocomplete="off"` — 브라우저 자동완성·자격증명 저장 차단 | 5,159개 (text · email · password · tel) |
| 페이지 타이틀에 `(Portfolio)` 표기 | 전 페이지 |
| 푸터 고지 — 비상업 학습 목적, 브랜드 비제휴, 실제 결제·개인정보 미수집 | 전 페이지 |

이후 재심사를 신청해 해결했습니다. 배포된 사이트는 **탐지 시스템의 판단 대상**이 되며, 재현도가 높을수록 오탐 가능성도 함께 올라간다는 것을 실제 사례로 확인한 작업이었습니다.

### 팝업 기본 숨김이 데스크탑에만 적용되던 구조적 버그

반응형 작업 중, 태블릿 폭에서 로그인·장바구니·검색 패널이 **페이지 본문 사이에 전부 펼쳐진 채 렌더링**되는 문제를 발견했습니다.

원인은 팝업·패널의 `display: none` 기본값이 `@media (min-width: 1280px)` 블록 안에 갇혀 있던 것이었습니다. 데스크탑에서는 정상이지만 그 외 폭에서는 "숨김" 자체가 적용되지 않았습니다.

**해결** — "기본 상태는 화면 크기와 무관하다"는 원칙으로 숨김 규칙을 미디어쿼리 밖 전역 스코프로 분리하고, `.active` 토글만 상태 규칙으로 남겼습니다. 이후 브레이크포인트를 추가해도 팝업 시스템을 다시 손댈 필요가 없어졌습니다.

### 반응형 이미지 오버플로우

배너·컬렉션 이미지가 고정 폭으로 지정되어 좁은 화면에서 가로 스크롤을 유발했습니다. 개별 이미지를 수정하는 대신 `reset.css`에 전역 안전장치를 두고, 예외가 필요한 곳만 개별 재정의하는 방식을 택했습니다.

```css
img { max-width: 100%; height: auto; }
```

`img` 단독 셀렉터는 특정도가 가장 낮으므로(0-0-1), `width`·`height`를 이미 지정한 컴포넌트 규칙 35개는 전부 그대로 우선합니다. 전역 규칙 도입 후 중복이 된 개별 선언 12줄은 제거했습니다.

### 이미지 962.8MB — 포맷 선택의 대가

상품 사진 3,410장이 전부 PNG였습니다. 700×880 사진 한 장이 2MB, 픽셀당 3.4바이트로 **사실상 압축이 걸리지 않은 상태**였습니다. PNG는 무손실 포맷이라 로고·아이콘에 적합하고 사진에는 부적합합니다.

WebP q85로 일괄 변환해 **962.8MB → 92.2MB(-90.4%)**로 줄였습니다. q80·q85·q90을 실제 변환해 비교한 뒤, PSNR 42dB로 여유가 있으면서 q90보다 25% 작은 q85를 선택했습니다. 니트·레이스처럼 미세 패턴이 있는 상품에서 q80은 기준선에 걸쳐 있었습니다.

전환 시 HTML 13,109곳의 경로를 교체했지만 **JS와 CSS는 한 줄도 고치지 않았습니다.** 호버 이미지 교체 로직이 확장자를 하드코딩하지 않고 정규식으로 도출하는 구조였기 때문입니다.

```javascript
var hoverSrc = this.src.replace(/(\.[^.]+)$/, '_hover$1');
```

655쌍의 호버 이미지가 `.png`에서 `.webp`로 바뀌어도 그대로 동작했습니다. 초기 설계의 선택이 3,410장 전환 상황에서 값을 한 사례입니다.

## 5. 접근성

- **랜드마크** — `header` / `nav` / `main` / `footer`를 **392페이지 전부**에 배치. 스킵 링크나 ARIA 속성 없이도 반복되는 헤더 메가메뉴를 건너뛰고 본문으로 이동할 수 있습니다 (WCAG 2.4.1 Level A)
- **문서 구조** — 페이지당 단일 `h1`, 브레드크럼 `nav > ol`
- **대체 텍스트** — 이미지 13,502개 전량에 콘텐츠 기반 `alt` 작성. 빈 `alt` 0건이며, 상품 이미지는 색상·소재 등 식별 정보를 포함합니다 (예: `alt="Loafer Bag In Pine Green Alligator Leather"`)
- **키보드 초점** — `:focus-visible` 전역 선언(`outline: 2px solid var(--gs06)` · `outline-offset: 2px`). 배경 대비 **13.16 : 1**이며, 검은 버튼 위에서는 `outline-offset`으로 링이 버튼 바깥에 그려져 대비를 확보합니다. 마우스 클릭 시에는 나타나지 않아 디자인을 해치지 않습니다
- **명도 대비** — 본문 `--gs05`(#333) / 배경 `--be01`(#f3ede3) 대비율 **10.85 : 1** — WCAG AA 기준(4.5:1)을 크게 상회
- **`title` 고유성** — 392페이지 전부 고유. 상품 상세는 카테고리 뒤에 상품명을, 주문 상태 페이지는 상태명을, 분할된 목록은 페이지 번호를 덧붙였습니다
- **폼 라벨** — 입력 요소 6,604개에 `label[for]` 100% 연결, 플레이스홀더로 라벨을 대체하지 않음
- **터치 타겟** — 모바일·태블릿 내비게이션 항목 높이 60px
- **확대 대응** — 폰트 크기의 순수 `vw` 단위 사용을 배제하는 원칙 적용 (사용자 확대 무력화 방지, WCAG 1.4.4). 잔여 8건은 `clamp()` 전환 예정

## 6. 한계와 다음 단계

현재 구조에서 스스로 인지하고 있는 한계입니다.

1. **의미 토큰 미이행** — `--c-text`, `--c-bg` 등 용도 기반 별칭 9종을 `:root`에 정의했으나 컴포넌트 CSS는 여전히 원시 토큰(`var(--gs05)`)을 직접 참조합니다. 실제 참조 **0회**로, "2계층 토큰 아키텍처"는 설계 의도이며 아직 구현되지 않았습니다. 이행이 끝나면 "브랜드 색 교체"와 "용도 변경"을 분리해 다룰 수 있게 됩니다. 역할 간격 토큰(`--gutter`, `--section-y`)도 공통 컴포넌트 층까지만 적용된 상태로, 페이지 레이아웃 층(page.css)으로의 확장이 다음 단계입니다.

2. **위치 기반 셀렉터 의존** — `header>div div:nth-of-type(2)` 형태의 구조 종속적 셀렉터가 다수 존재합니다. 마크업 순서가 바뀌면 스타일이 깨지는 취약성이 있어, 차기 프로젝트에서는 SCSS + BEM 기반 클래스 설계로 전환합니다.

3. **체크박스 토글의 키보드 접근 불가** — 햄버거 메뉴·사이드 메뉴·동의 체크박스가 `display: none`으로 숨겨져 있습니다. `display: none`은 탭 순서에서 완전히 제외되므로, `:focus-visible`을 정의해도 **초점 자체가 도달하지 못합니다.** 특히 결제 약관 동의가 포함되어 키보드만으로는 주문 완료가 불가능합니다. 시각적 숨김(`clip-path` 등) 방식으로 교체하는 것이 우선 보완 대상입니다.

4. **영상 439MB** — 이미지를 92MB로 줄이면서 영상이 게시 용량의 83%를 차지하게 됐습니다. 61개 파일을 298곳에서 재사용하는 구조 자체는 효율적이나, 전부 `autoplay`라 화면 밖에서도 다운로드됩니다. `IntersectionObserver` 기반 지연 로드와 재인코딩이 다음 과제입니다.

5. **CSS 로드 방식** — `@import` 7단 체인은 직렬 로딩됩니다. `<link>` 병렬 로드로 전환하면 요청 1왕복을 줄일 수 있으나, CSS 총량이 8,806줄(압축 시 수십 KB)로 작아 실측 이득이 0.1~0.3초에 그치는 반면 392개 HTML의 `<head>` 순서가 하나라도 어긋나면 전면 스타일 붕괴로 이어집니다. **이득 대비 회귀 위험을 평가해 현 구조를 유지하기로 결정**했으며, 진입점이 `import.css` 하나로 단일화되어 로드 순서를 한 파일에서 관리할 수 있다는 이점도 함께 고려했습니다. 향후 CSS 총량이 크게 늘면 재검토합니다.

6. **외부 의존 버전 미고정** — jQuery를 `code.jquery.com/jquery-latest.min.js`로 로드합니다. jQuery 재단이 2014년에 갱신을 중단한 별칭 URL이라 어떤 버전이 내려오는지 고정되지 않습니다. 고정 버전 URL로 교체가 필요합니다.

7. **상태 관리 부재** — 장바구니·위시리스트가 화면 표현에 머물러 새로고침 시 초기화됩니다. `localStorage` 기반 지속성 부여가 다음 기능 과제입니다.

8. **jQuery 의존** — 학습 곡선상의 선택이었으며, 인터랙션 로직의 Vanilla JS 전환을 검토 중입니다.
